# Status Check "Not Found" Issue - Explanation & Solution

## The Problem in Your Logs

```
Translation job a63bc0c1-69aa-40fb-a840-fd1f626e2eec started successfully  ? Your app's Job ID
Translation job a63bc0c1-69aa-40fb-a840-fd1f626e2eec started with status Completed

Checking status for translation job a63bc0c1-69aa-40fb-a840-fd1f626e2eec  ? UI is polling
Translation job a63bc0c1-69aa-40fb-a840-fd1f626e2eec not found in Azure Translation Service  ? Not found!
```

## Why This Happens

### Two Different IDs:
1. **Your App's Job ID**: `a63bc0c1-...` (generated by `Guid.NewGuid()`)
2. **Azure's Operation ID**: `a2421176-...` (returned by Azure Translation Service)

### The Flow:
1. App creates job ID: `a63bc0c1...`
2. App creates containers: `job-a63bc0c1...-source` and `job-a63bc0c1...-target`  
3. App starts translation, Azure returns operation ID: `a2421176...`
4. App waits for completion (**blocks until done**)
5. App returns `jobId: "a63bc0c1..."` to UI
6. UI tries to check status with `jobId: "a63bc0c1..."`
7. `GetTranslationStatusAsync` searches Azure for `a63bc0c1...` ?
8. Azure only knows about `a2421176...` ?
9. **Not found!**

## Why Downloads Still Work

Downloads work because:
- Files are in container: `job-a63bc0c1...-target/filename.docx` ?
- Download path uses: `job-a63bc0c1...-target/filename.docx` ?
- **Container name matches job ID!** ?

The "not found" issue is **only for status checking**, not downloads.

## The Real Question: Why Is UI Polling?

Looking at your code, the translation **waits for completion**:
```csharp
await operation.WaitForCompletionAsync(cancellationToken);  // Blocks!
response.Status = "Completed";  // Already done
response.TranslatedFiles.Add(...);  // Files populated
```

Since the response already says **"Completed"** with all files populated, the UI shouldn't be polling at all!

### Check Your JavaScript:

In `Index.cshtml`, the form submission handler should be:
```javascript
const result = await response.json();

if (result.status === 'Completed' && !result.isAsync) {
    // Sync completed - show results immediately
    displaySyncResults(result);  // Should show files immediately
} else if (result.isAsync || result.status === 'InProgress') {
    // Async or still processing - start polling
    startStatusPolling(result.jobId);
} else {
    // Error
    throw new Error(result.errorMessage || 'Translation failed');
}
```

## Solution Options

### Option 1: Fix the UI (Recommended)
**The UI shouldn't be polling if status is "Completed".**

Make sure your JavaScript checks:
```javascript
if (result.status === 'Completed') {
    // Already done! Show results immediately
    displaySyncResults(result);
} else if (result.status === 'InProgress') {
    // Start polling
    startStatusPolling(result.jobId);
}
```

### Option 2: Also Cache Operation ID Mapping
If you still want status checking to work, map job ID to operation ID:

```csharp
// In DocumentTranslationService class
private readonly Dictionary<string, string> _jobIdToOperationId = new();

// In ProcessBatchTranslationAsync after getting operationId:
lock (_operationsLock)
{
    _jobIdToOperationId[jobId] = operationId;  // Map them
    _activeOperations[operationId] = operation;
}

// In GetTranslationStatusAsync:
public async Task<JobStatus> GetTranslationStatusAsync(string jobId, ...)
{
    // Try to map job ID to operation ID
    string searchId = jobId;
    lock (_operationsLock)
    {
        if (_jobIdToOperationId.TryGetValue(jobId, out var operationId))
        {
            searchId = operationId;  // Search by operation ID instead
            _logger.LogInformation("Mapped job ID {JobId} to operation ID {OperationId}", 
                jobId, operationId);
        }
    }
    
    // Search for searchId (which might be operation ID now)
    await foreach (var status in _batchClient.GetTranslationStatusesAsync(...))
    {
        if (status.Id == searchId)  // Compare with operation ID
        {
            // Found it!
            var jobStatus = new JobStatus
            {
                JobId = jobId,  // Return original job ID to UI
                Status = status.Status.ToString(),
                // ...
            };
            return jobStatus;
        }
    }
}
```

### Option 3: Don't Wait for Completion (Not Recommended for This Issue)
Remove `await operation.WaitForCompletionAsync()` and return immediately:
- Response status would be "InProgress"
- UI would poll for status (using operation ID)
- But downloads would break because you wouldn't know when files are ready

## Recommended Approach

**Option 1 is best** because:
1. ? No code changes needed
2. ? UI already gets "Completed" status
3. ? Files are already populated
4. ? Downloads already work
5. ? No need for status polling

Just make sure your UI checks `result.status === 'Completed'` and shows results immediately instead of polling.

## Summary

- ? **Problem**: UI is polling for status even though job is already "Completed"
- ? **Solution**: UI should check `status === 'Completed'` and show files immediately
- ?? **Status "Not Found"**: Expected because Azure doesn't know your job ID (only operation ID)
- ? **Downloads Work**: Because container names use your job ID, which is correct

The "not found" messages are harmless - they only occur if UI unnecessarily polls for status. The real issue is that the UI shouldn't be polling at all since the job is already complete when the response is returned!
